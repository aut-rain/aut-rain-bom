# 1.1.0（待发布）

## 变化

新增 `com.xuxueli:xxl-job-core:3.3.0` 依赖管理，版本属性为 `xxl-job.version`。按新增受管理依赖的版本策略，BOM 从 `1.0.0` 升为 `1.1.0`。其余依赖管理保持不变。

## 版本选择

核查日期：2026-10-19。Maven Central 最新正式版为 `3.5.0`；本次选择与当前技术栈一致的正式版本 `3.3.0`，不是声称它是全社区最新版本或仍有长期支持保证。

| XXL-JOB 版本 | 上游 Spring Boot / Spring | 本次考虑 |
| --- | --- | --- |
| 3.3.0 | 3.5.8 / 6.2.14 | 与本 BOM 的 Boot 3.5 技术基线一致 |
| 3.3.1 | 4.0.0 / 7.0.1 | 上游已迁移 Boot 4 |
| 3.4.2 | 4.1.0 / 7.0.8 | 上游已迁移 Boot 4 |
| 3.5.0 | 4.1.1 / 7.0.9 | 最新正式版，另有执行器级 AccessToken 与通信协议变化 |

上游基线不同并不直接证明新版 SDK 无法在 Boot 3 下工作，但不应在缺少运行时验证的情况下默认替换。后续迁移到新版时，需验证执行器与调度中心通信、访问令牌和数据库升级要求。

仅管理执行器 SDK，不导入 XXL-JOB 父 POM，避免引入其整套依赖管理规则。Netty、Gson、Groovy 等传递依赖仍受本 BOM 已导入的 Spring Boot BOM 管理，最终解析版本应以使用方依赖树为准。

## 使用方接入

1. 发布后将 BOM 引用更新为 `1.1.0`；发布前先在本地安装待发布 BOM。
2. 声明 `com.xuxueli:xxl-job-core`，省略版本。
3. 按官方 Spring Boot 示例配置执行器 Bean 和任务处理器。SDK 不会自动创建执行器。
4. 独立部署相同版本调度中心，验证执行器注册、调度、日志、回调、失败处理和停机行为。

本次只增加依赖管理，没有部署调度中心，也没有完成服务之间的调度联调。版本稳定性不能仅由正式版本号或 Maven 解析成功推断。

## 已完成验证

- `mvn -o validate help:effective-pom`：模型解析通过，`xxl-job-core` 最终管理版本为 `3.3.0`。
- `mvn -o install`：已安装 `1.1.0` 到本机 Maven 仓库，用于发布前试用。
- 独立临时消费工程导入 `1.1.0`，无版本声明地依赖 `xxl-job-core` 和 `spring-boot-starter`，`mvn dependency:tree` 解析通过。
- 最终依赖树包含 Spring Boot `3.5.11`、Spring Context `6.2.16`、Netty `4.1.131.Final`、Gson `2.13.2`、Groovy `4.0.30`、xxl-tool `2.3.2`。

注意：XXL-JOB 上游声明 Netty `4.2.7.Final`，消费方因 Boot BOM 管理解析为 `4.1.131.Final`。本次没有全局升级 Netty，避免影响其他组件；发布前应验证执行器嵌入服务器启动与调度通信。本次未执行这些运行时测试。
